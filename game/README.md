# 三国火纹 · 首关工程

首关「桃园结义」采用 1024×768 完整底图与 16×12 独立逻辑网格。玩家操作刘备、关羽、张飞迎战五名黄巾剑兵与一名头目；歼灭全部敌人获胜，任意一位兄弟败退即失败。胜利剧情结束后简雍加入队伍，并保存首关完成状态。

这是 M1 教学原型。首关数值、成长率和失败规则采用 GDD v1.3 的建议默认值，仍可依据游玩反馈调整。后续章节、计策、转职、爆气和 IF 路线保留规划，未开放入口。

## 安装与运行

需要 Node.js 20.19 或更高版本。以下命令在本目录执行：

```sh
npm ci
npm run dev -- --port 5174
```

打开 [http://127.0.0.1:5174/](http://127.0.0.1:5174/)。5173 端口在当前工作环境中被其他任务占用；若 5174 也被占用，可改用另一个空闲端口。服务启用了严格端口检查，不会悄悄跳转端口。

`public/art/` 已包含首关所需素材与来源清单，首次运行无需导入或手工复制图片。依赖安装后，运行游戏不需要在线 AI 服务或后端。

## 操作

| 操作 | 方法 |
| --- | --- |
| 选择武将、查看信息 | 点击地图单位或右侧我方名册；敌军也可查看属性 |
| 预移动 | 选择尚未行动的我方单位，点击蓝色落点；悬停或移动光标可预览路径 |
| 攻击 | 在行动菜单选择「攻击」，选目标后查看双方预测，再「确认交战」 |
| 伤药 | 行动菜单选择「使用伤药」；每人 3 次，每次恢复 10 HP，消耗行动 |
| 待机 | 保留当前位置或预移动落点，结束该单位行动 |
| 撤销与返回 | Esc 或右键逐层返回；行动菜单中的「撤销移动」恢复预移动前位置 |
| 地图键盘操作 | 方向键移动光标，Enter 确认；菜单中 Tab 切换按钮、Enter 执行 |
| 推进对白 | Enter、空格或对话按钮；先补全当前句，再进入下一句；已读段落可跳过 |
| 网格 / 敌方威胁 | 界面复选框，或在地图操作时按 G / T |
| 结束阶段 | 点击「结束我方阶段」；未行动武将也会结束本阶段，敌军依次行动 |
| 动画速度 | 战场下方或「设置」选择正常、2 倍、4 倍 |
| 失败后重试 | 结算页选择「重新挑战」，使用本局相同种子重新部署 |

预移动只影响预览，尚未消耗行动、伤药或随机数；提交攻击、道具或待机后即结算，动画仅播放结果。正常与快进使用同一规则，速度变化不会重新掷随机数。

剑克刀斧，刀斧克枪，枪克剑；优势命中 +15、攻击 +1，劣势反向扣减。张飞的枪克制黄巾剑兵，关羽的刀斧受到剑兵克制。林地代价为 2，防御 +1、回避 +15；可穿过我方单位，但不能与任何单位重叠停留。

## 随机种子与存档

默认随机种子为 `20261104`，可在「设置」中修改下一次新征战的种子。相同初始状态、种子和行动序列可复现战果；查看战斗预测不消耗随机数。

存档使用浏览器 `localStorage`，键为 `sanguo-fire-emblem.save.v1`。仅有一个本地进度槽，不提供云同步或跨设备同步。同一协议、主机和端口共享该槽；更换端口、浏览器或用户配置目录会看到另一份本地存储。清理站点数据会删除进度。

- 开场剧情结束、每次重新进入我方阶段、胜利剧情完成后自动保存；我方可操作的稳定状态也可手动保存。
- 预移动、行动动画与敌军阶段不能创建半完成存档；这些时刻刷新页面会回到最近一次有效保存。
- 保存关卡、回合与阶段、单位属性与位置、伤药、经验、行动/存活状态、队伍、剧情标志、地图状态和随机数状态；图片与动画计时器不写入存档。
- 「继续征战」读取最近一次有效保存；首关完成存档进入结算，不重复发放经验或招募简雍。简雍只记录为战后入队成员，不成为首关可操作单位。
- 读取时检查版本与完整性；不兼容或损坏的存档显示错误并保留原始数据。随后开始新征战并产生自动保存，会覆盖单槽中的旧记录。
- 浏览器限制本地存储或空间不足时会提示保存失败；当前页面仍可游玩，但不能据此认为进度已经保存。

## 资源来源与重新导入

美术权威入口是源库的 `assets/v2/manifest.json`，当前接入主库 v2.1.1、小人 v2.0.4。游戏侧特殊映射位于 `src/data/art-mapping.json`；只复制首关所需身体、掌部前景、rig（逐帧挂点）、武器、副手、地图、立绘、UI 与特效依赖，不修改源库。

只有更新或更换原美术包时才需要重新导入：

```sh
ART_PACK_ROOT="/你的路径/三国火纹美术资源包" npm run import:assets
npm run check:assets
```

未设置 `ART_PACK_ROOT` 时，默认读取 `/Users/didi/Documents/ChatGPT/三国火纹美术资源包`。导入器生成 `public/art/manifest.json` 与 `public/art/import-manifest.json`，记录源资源 ID、相对路径、字节数和 SHA256；缺失依赖会报告具体路径。

刘备、张飞、关羽使用已有职业通用身体，以头像、姓名、武器和技能区分人物。关羽暂用 `danyang_player`，青龙偃月刀的美术类别 `blade` 与玩法类别 `axe` 分开配置；黄巾剑兵使用游戏侧剑类适配。身体不是专属人物重绘。小人只有朝右 3/4 视角与左向镜像，上下移动沿用最近左右朝向。

[九动作检视入口](http://127.0.0.1:5174/?inspect=1) 使用实际游戏渲染器，可暂停与切换朝向，检查刘关张、黄巾兵的身体、独立武器、原生掌部遮挡及九动作。素材接入检查与用户视觉验收是不同结论。

## 地图说明与已知限制

`src/data/chapter1.json` 是通行、地形、部署与胜负条件的权威数据。192 个格子均已人工标注，74 个可通行格全部连通，9 个部署点合法；浓密树冠及具体树干通过 `blocked` 显式阻挡，其他林地仍可行走。没有独立前景遮挡层，因此路线避开屋顶和需要穿行其后的大树。

左侧桥与两端道路可通行。底部桥与西岸不适配 64 像素网格，首版将其保留为不可达景观；该区域待美术返修，本关目标不依赖它。桥梁与建筑均为静态景物，不可破坏。

[地形检查图](evidence/chapter1-terrain-check.png) 展示真实底图、坐标、逐格地形与部署位置；[地图结构检查报告](evidence/chapter1-map-check.json) 记录数量和连接检查结果。检查图属于人工标注证据，不能代替实际游戏移动验收。

## 检查与生产构建

```sh
npm run typecheck
npm test
npm run check:map
npm run check:assets
npm run build
npm run preview -- --port 4174
```

| 命令 | 检查范围 |
| --- | --- |
| `typecheck` | TypeScript 类型检查 |
| `test` | 纯规则测试，包括寻路、战斗、状态、随机、AI 与存档 |
| `check:map` | 格子完整性、地形、部署、连接与桥头；生成地图检查报告 |
| `check:assets` | 导入依赖、SHA256、尺寸、图集/rig 与映射一致性 |
| `build` | 类型检查与 Vite 生产构建 |
| `preview` | 通过 HTTP 预览生产产物 |

构建输出在 `dist/`，`base: './'` 使静态资源采用相对 URL。部署时保留整个目录结构，通过任意合适的 HTTP 静态服务器提供服务，可放在子目录。不要用 `file://` 打开构建文件，也不需要浏览器访问开发机原美术库的绝对路径。首版没有 Service Worker，不承诺已关闭服务器后仍能通过浏览器缓存离线打开。

具体规则测试、构建和浏览器实玩证据见[首关需求记录](../.agentdocs/workflow/REQ-20261104141123-首关可玩原型/README.md)。浏览器通关、失败重试、保存继续及用户视觉验收分别记录，不以构建成功替代。

## 目录职责

| 目录 | 内容 |
| --- | --- |
| `src/core/` | 不依赖 DOM 的坐标、寻路、战斗、AI、随机、存档规则与测试 |
| `src/data/` | 规则数值、人物与武器、地图、对白、规划和美术映射 |
| `src/render/` | Canvas 地图、身体与武器装配、特效和资源缓存 |
| `src/ui/` | React 菜单、信息面板、键鼠交互与动画调度 |
| `public/art/` | 已导入的首关运行素材及来源清单 |
| `scripts/` | 资源导入、素材与地图检查 |
| `evidence/` | 可追溯的检查报告与验证图，实际验收状态见需求记录 |

M2 再推进第 2—4 关、计策、后勤与友军行动；M3 扩展剧情、成长、转职和招募；M4 接入模块化地图。内容状态区分 `planned`（规划）、`draft`（制作中）与 `playable`（已达到相应可玩验收），后续规划不会自动出现在开始游戏菜单。
