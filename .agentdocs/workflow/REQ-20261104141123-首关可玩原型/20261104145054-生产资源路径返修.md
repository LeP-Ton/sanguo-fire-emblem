## 发现与原因

在准备结束静态预览时核对 HTTP 日志，发现 `panel_blue`、`panel_red`、`hp_fill`、`bar_frame` 的 CSS 请求被解析为 `/dist/assets/art/...` 并返回 404。此前浏览器加载器已成功解码 48 张 PNG，但它们通过 JS 图片对象访问正确地址；CSS 自定义变量中的相对 `url(...)` 则依据最终消费该变量的外部样式表地址解析。

因此，先前“加载器成功、页面无脚本错误”不能当作所有资源使用位置均已验收。[先前报告](../../../game/evidence/browser/qa-report-before-css-fix.json)及截图 14 保留为历史证据；该项由本记录的返修验证替代，核心规则及通关结论不受影响。

## 修改

- `game/src/render/index.ts`：资源路径统一用 `new URL(path, document.baseURI)` 生成当前站点完整 URL；HTML、Canvas 和 CSS 使用同一地址，不硬编码主机或开发机路径。
- `game/index.html`：使用已有经验图标作为 favicon，避免浏览器额外请求根目录不存在的图标。
- 不修改任何美术文件、战斗数值或存档版本。
